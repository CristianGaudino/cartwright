# Phase 1: Design and Stock Browsing - Context

**Gathered:** 2026-11-03
**Status:** Ready for planning

<domain>
## Phase Boundary

A buyer can find a car on their phone, fast: browse, search, filter and sort the stock in a modern look built around the locked logo. Delivers the design contract (done: `01-UI-SPEC.md`), the `StockProvider` interface with a file-backed demo provider, the `/used-cars` stock page with filters, sort, URL state and facet counts, the swipeable lazy-loaded photo carousel on cards, and the written CarsIreland/Carsie investigation. Issues #2, #3, #4, #5, #16 (requirements DES-01, STK-01..04, BRW-01..05).

Car detail content, share, landing pages, saved cars and forms are later phases. Phase 1 only ships a bare detail route so cards never 404.

</domain>

<decisions>
## Implementation Decisions

The UI-SPEC (`01-UI-SPEC.md`, approved) already fixes palette, type, spacing, layout, filter groups, URL params, sort keys, card and carousel behaviour, motion and copy. Those are not repeated here and are not reopened.

### Demo stock data
- **D-01:** The demo cars are the **real listings currently on cartwright.ie**, scraped once (make, model, variant, year, mileage, fuel, transmission, body type, price, photos). Target roughly 60 cars; use however many the site lists if it differs, and say so in the plan. — **Reversibility:** reversible — the file is regenerated by script and replaced by the CarsIreland/Carsie provider later.
- **D-02:** The data file is **generated by a seeded/deterministic script and the output is committed** (matches CLAUDE.md "generated file-backed provider"). The script lives in the repo so the file can be regenerated or resized. — **Reversibility:** reversible — script plus committed output.
- **D-03:** Photos are **copied into the repo as resized files**, not hotlinked, so the demo survives the client removing listings (no R2 set up yet, owner does not want it). Resize to the UI-SPEC image size (1200 x 900, 4:3), compressed (WebP or AVIF), at most 6 per car (UI-SPEC cap). The planner chooses the count per car and the format so the repo and the Workers static assets stay reasonably small (rough budget: aim well under 30 MB total; fewer photos per car is acceptable if "several" is still met). — **Reversibility:** costly — committed binaries are permanent in git history and affect repo size.
- **D-04:** The photos and listing data belong to the dealer and CarsIreland. Use is for the private pitch demo only. The plan must record that they are replaced by the client's feed or supplied images before any public launch, and the scrape script must be polite (low rate, identifies itself generically, one run). — **Reversibility:** reversible — flagged in docs.

### Provider contract
- **D-05:** `StockProvider` takes a **query** (filters, sort, page, page size) and returns **the page of cars, the total, and facet counts for the current selection**. Pages never filter, sort or count themselves. The demo file provider does this in memory; a CarsIreland provider can push it to its API. Also exposes get one car by slug/id (STK-01). — **Reversibility:** costly — every page and the future provider depend on this signature.
- **D-06:** Exactly **one config point** selects the active provider; pages import only that, never a concrete provider. — **Reversibility:** reversible.
- **D-07:** STK-03 is proven by a **contract test**: the same filter, sort, page and facet assertions run against the file provider and a small in-test stub provider. If a page had to change to use the stub, the test design is wrong. — **Reversibility:** reversible.

### Interim card link
- **D-08:** Cards link to the **final URL `/used-cars/[slug]`**, backed by a **minimal real page** in Phase 1 (title, price, photos, spec basics, a link back to the stock page). Phase 2 fills it in without changing any URL. An unknown slug returns a 404 (the 410 behaviour for sold cars is Phase 2, CAR-02). A test must show no card link ends in a 404. — **Reversibility:** costly — the slug scheme becomes a public URL and SEO surface; keep slugs stable and derived from make, model, year and a stable id.

### CarsIreland/Carsie investigation (#16)
- **D-09:** The write-up is **`docs/carsie-feed.md` in the repo**, linked from #16: feed and auth model, rate limits, terms, data fields mapped to the `StockProvider` types, what is unknown until the client has access. A real provider is built only if access exists (not assumed). #16 closes on the written investigation. — **Reversibility:** reversible.

### Owner decisions after research (2026-11-03, before planning)
- **D-10 (extends D-04):** The owner authorises **one scripted call** to cartwright.ie's own `POST /wp-json/api/v2/search/cars` (nonce read from the page, generic user agent) to list all the cars (about 57 at research time). The response shape is unverified: the scraper saves the raw response, inspects it, and fails loudly if it differs from what the code expects. No second call without the owner. — **Reversibility:** reversible (cached locally, one run).
- **D-11 (amends D-03):** Photos are **6 per car, WebP quality 72, 900 x 675** (4:3). This replaces D-03's and the UI-SPEC's 1200 x 900 because the source photos are 938 x 704 and 1200 x 900 would be an upscale. A **3-car trial** runs first and its real size is reported to the owner at a blocking checkpoint **before** the full set is generated and committed. — **Reversibility:** costly (committed binaries stay in git history).
- **D-12:** The site **header is not sticky**. On the stock page only the filter bar is sticky (and the desktop filter sidebar, per the UI-SPEC layout table). — **Reversibility:** reversible.

### Owner decision during plan check (2026-11-03)
- **D-13 (extends D-01 and D-10):** Besides the one listing POST, the owner authorises these requests to www.cartwright.ie, as a **one-time run**: one GET of `/used-cars/` and one GET of the theme's `main.js` (to read the nonce and the request shape), and one GET of `/car-details/` per car (about 57, at least 1.5 s apart) **only when the listing lacks that car's specs**. Photos come from the Carsie CDN (`c0.carsie.ie`) as in D-03. No retry loops: a failed request stops the run. The 3-car trial reports **every request sent to www.cartwright.ie**, and the full fetch runs **only after** the owner approves the trial at its checkpoint. **Reversibility:** reversible (cached locally, one run).

### Claude's Discretion
- Photo format, per-car photo count and exact size budget (D-03), within the cap of 6 and the 1200 x 900 box.
- `next/image` optimiser versus plain `<img>` on OpenNext/Workers (UI-SPEC says check `node_modules/next/dist/docs/` first). With pre-resized static files, plain `<img>` is likely enough.
- Slug format details, file layout, test structure, and how the minimal car page is laid out, within the UI-SPEC tokens.
- Whether the scrape is a one-off script kept in `scripts/` or documented only; it must not run in CI or at build time.

</decisions>
