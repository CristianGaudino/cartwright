# Phase 1: UI Design Contract

> Visual and interaction contract for Design and Stock Browsing (issues #2, #4, #5; #3 and #16 have no UI). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Brand asset (locked)

The logo is the only locked asset. It is not in the repo. Source: `https://www.cartwright.ie/app/uploads/2024/09/logo.png` (PNG, 650 x 270, RGBA, transparent background).

Consequences the executor must follow:

## Spacing Scale

Declared values (all multiples of 4). Implement in `rem` (4px = 0.25rem) so layout scales with the user's text size; Tailwind v4's default `--spacing: 0.25rem` already matches, so `p-4` = 16px.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, dot gaps, inline padding |
| sm | 8px | Chip gaps, meta row gaps, carousel dots |
| md | 16px | Card text padding, default gap between controls, page gutter on mobile |
| lg | 24px | Gap between cards, page gutter from 640px, section padding |
| xl | 32px | Sidebar to grid gap, page gutter from 1024px |
| 2xl | 48px | Space above the page heading, between major blocks |
| 3xl | 64px | Space above footer, empty-state vertical padding |

Exceptions:

- Touch targets are a minimum of **44px** by 44px (a multiple of 4). Controls with a smaller visible shape (the 8px carousel dot is not a control; the 24px icon in a button is) get padding to reach 44px. Primary buttons and inputs are **48px** high.
- Header height is 56px on mobile and 64px from 1024px.
- Page content max width is 1280px, centred.

## Typography

Exactly four sizes (14, 16, 20, 32) and two weights (400, 600). Tracking is size-specific (apple-design section 15): tighter as text grows, never one value for all.

| Role | Size | Weight | Line Height | Tracking | Use |
|------|------|--------|-------------|----------|-----|
| Body | 16px | 400 | 1.5 | 0 | Paragraphs, input text, select text |
| Body strong | 16px | 600 | 1.5 | 0 | Card title, button label, filter group title |
| Meta | 14px | 400 | 1.4 | 0.01em | Card meta line, helper counts, result count, pagination text |
| Label | 14px | 600 | 1.4 | 0.01em | Chips, badges, small buttons, field labels |
| Heading | 20px | 600 | 1.2 | -0.01em | Card price, sheet title, empty state heading |
| Display | 32px | 600 | 1.1 | -0.02em | Page heading ("Used cars") |

Rules: no font size outside this table. Prices use `font-variant-numeric: tabular-nums`. Body text on a translucent surface keeps weight 600 for Label and Body strong only (vibrancy, apple-design section 12), never lighter than 400.

## Layout

Mobile first. One column is the base design; wider layouts add to it.

| Breakpoint | Width | Page gutter | Result columns | Filters |
|-----------|-------|-------------|----------------|---------|
| base | < 640px | 16px | 1 | Bottom sheet, opened from a sticky bar |
| sm | >= 640px | 24px | 2 | Bottom sheet |
| lg | >= 1024px | 32px | 2 | Sticky left sidebar, 280px wide, 32px gap to the grid |
| xl | >= 1280px | 32px (content max 1280px, centred) | 3 | Sticky left sidebar |

Route (default): the stock page lives at `/used-cars`, so the Phase 2 landing pages (`/used-cars/audi`, `/used-cars/suv`) nest under it. Pagination is `?page=n`, 12 cars per page (divides evenly into 1, 2 and 3 columns).

Stock page, top to bottom on mobile:

1. Header (ink, 56px, logo left, nav right; Phase 1 nav is the single item "Used cars" because every link must point at a real page; later phases add items)
2. Page heading "Used cars" (Display), then the result count (Meta)
3. Search input (48px, full width)
4. **Sticky bar** under the header: "Filters" button (left, with applied-count badge) and Sort select (right). 56px high. Translucent: `rgba(245,245,247,0.8)` with `backdrop-filter: blur(20px) saturate(180%)`, a bright 1px top edge, and no divider (apple-design section 12). This is the only blurred surface on the page; the header is solid ink so blur cost stays low on mid-range phones
5. Applied-filter chips row (wraps onto extra lines, never scrolls sideways), then "Clear all filters"
6. Results grid, 24px gaps
7. Pagination (hidden when there is one page)

**Primary focal point:** the first result card's price (Heading, 20px, weight 600, text primary) directly under the first photo. It is the one thing a car shopper scans first, and the page heading is deliberately quiet (Display 32px but no accent, no imagery) so the eye moves down to the cars. The only accent fill above the fold is the Filters badge, which stays small. Do not add a hero, banner or second emphasised element above the grid.

From 1024px: the sidebar holds search, then filter groups; the sticky bar is hidden; the count and Sort sit in one row above the grid; applied chips sit above the grid.

### Filter groups (order, control, behaviour)

| Group | Control | Notes |
|-------|---------|-------|
| Search | Text input, type=search | Free text over make, model and variant. Max 80 characters, trimmed |
| Make | Checkbox list with counts, e.g. "Audi 12" | Multi-select. Shows the top 8 by count, then "Show all {n}" |
| Model | Checkbox list with counts | Only rendered once at least one make is selected. Lists models of the selected makes |
| Year | Two selects, "From" and "To" | Newest year down to oldest |
| Budget | Two selects, "Min" and "Max" | Steps of EUR 2,500 to 10,000, then EUR 5,000 steps |
| Body type | Chips with counts | Multi-select |
| Fuel | Chips with counts | Multi-select |
| Transmission | Segmented control: Any, Manual, Automatic | Single-select |
| Mileage | One select "Up to" | Any, 20,000 km, 50,000 km, 80,000 km, 100,000 km, 150,000 km |

Counts are facet counts from the `StockProvider` for the current selection. An option whose count is 0 stays visible, is `aria-disabled`, and is shown in secondary text, unless it is currently selected (selected options stay enabled so they can be unticked).

Filters apply **instantly** on every change, in the sidebar and in the sheet. There is no separate apply step. In the mobile sheet the bottom button is just "Show n cars", which closes the sheet.

### URL contract (BRW-03)

State lives in the query string of `/used-cars`. Lowercase slugs, comma separated for multi-values, omitted when default. Filter changes use `router.replace` (no history entry per click); the page param and sort changes also replace.

| Param | Example | Meaning |
|-------|---------|---------|
| `q` | `q=a4` | Search text |
| `make` | `make=audi,bmw` | Makes |
| `model` | `model=a4,a6` | Models |
| `yearFrom`, `yearTo` | `yearFrom=2018` | Year range |
| `priceMin`, `priceMax` | `priceMax=20000` | Budget in EUR |
| `body` | `body=suv,hatchback` | Body types |
| `fuel` | `fuel=diesel,hybrid` | Fuel types |
| `gearbox` | `gearbox=automatic` | Transmission |
| `kmMax` | `kmMax=100000` | Maximum mileage in km |
| `sort` | `sort=price-asc` | Sort key (below) |
| `page` | `page=2` | Page number, default 1 |

Unknown params and invalid values are ignored, never an error. A `page` past the last page redirects to the last page.

### Sort

Native `<select>`. Options and keys:

| Label | Key |
|-------|-----|
| Newest listed (default) | `newest` |
| Price: low to high | `price-asc` |
| Price: high to low | `price-desc` |
| Year: newest first | `year-desc` |
| Mileage: lowest first | `km-asc` |

## Listing card

An `<article>` on a white surface, 16px corner radius, hairline border `#E2E2E6`, no shadow at rest. Corner radius scale: card 16px, controls (inputs, selects, buttons, chips use full pill) 12px.

Top to bottom:

1. **Photo area**: fixed `aspect-ratio: 4 / 3`, background `#E9E9ED`, photos `object-fit: cover`. The box is reserved before any image loads, so there is no layout shift.
2. **Text block**, 16px padding, 4px between lines:
   - Price: Heading, tabular numbers, formatted `€18,950` (locale `en-IE`)
   - Title: Body strong, `{make} {model} {variant}`, clamped to 2 lines
   - Meta: Meta, secondary colour, `{year} · {mileage} km · {fuel} · {transmission}`, allowed to wrap to 2 lines. A missing field is dropped with its separator, never shown as blank or "undefined"

A 44px slot at the top right of the photo area is reserved for the Phase 3 save button. Do not render anything there in Phase 1.

### Carousel (BRW-05)

- Native **CSS scroll-snap**: `overflow-x: auto; scroll-snap-type: x mandatory; overscroll-behavior-x: contain`, hidden scrollbar, each slide `flex: 0 0 100%` with `scroll-snap-align: start`. No carousel library: the browser supplies 1:1 finger tracking, momentum, rubber-banding and interruptibility (apple-design sections 2, 3, 6, 9).
- Up to **6** photos per card. Each slide is an `<a>` wrapping the image, linking to the car page, with `tabindex="-1"` and `aria-hidden="true"`; the title link is the one accessible link to the car. A swipe never navigates; a tap on the photo does.
- **Loading**: slide 1 is a normal image; slides 2 to 6 are `loading="lazy"` with `decoding="async"`. Only the first photo of the first two cards uses `fetchpriority="high"` and eager loading (LCP); every other card is fully lazy. All images carry explicit `width`/`height` (1200 x 900) and `sizes="(min-width:1280px) 33vw, (min-width:640px) 50vw, 100vw"`. Check `node_modules/next/dist/docs/` for `next/image` behaviour on OpenNext/Workers before choosing between the optimiser and plain `<img>`.
- **Dots**: 8px circles, 8px gap, centred 16px from the photo bottom, white on a soft dark shadow (`0 0 2px rgba(0,0,0,.5)`), active dot 100% white, others 55%. Hidden when the car has one photo. Decorative (`aria-hidden`); position tracked from scroll position on `requestAnimationFrame`.
- **Arrows** (pointer devices only, `@media (hover: hover)`): 44px circular buttons, white at 85% with blur, chevron icon, vertically centred, 8px from each edge, shown on card hover and on `:focus-within`, hidden at the first and last slide. They call `scrollBy` one slide width. Labels: "Previous photo" and "Next photo". On touch devices there are no arrows.
- **Semantics**: the scroller has `role="group"`, `aria-roledescription="carousel"` and `aria-label="Photos of {year} {make} {model}"`. Each slide has `role="group"`, `aria-roledescription="slide"` and `aria-label="Photo {i} of {n}"`. Image `alt` is `{year} {make} {model}, photo {i} of {n}`.
- **No photos**: show the `#E9E9ED` box with the text "No photo yet" (Meta, centred). No dots, no arrows.
- **Image fails to load**: keep the reserved box and show nothing broken (no browser broken-image icon).

## Motion

Principles from apple-design: respond on press, never lock input, animate from the current value, springs where a gesture is involved, restraint everywhere else. Animate only `transform` and `opacity`.

| Interaction | Behaviour | Values |
|-------------|-----------|--------|
| Press feedback (buttons, chips, cards) | Instant on pointer-down, release on pointer-up | `:active { transform: scale(0.97); transition: transform 100ms ease-out }` |
| Card hover (pointer devices only) | Soft lift, no scale | `box-shadow: 0 8px 24px rgba(17,17,20,.08)`, 200ms ease-out |
| Carousel swipe | Native scroll-snap, 1:1 tracking, native momentum | No custom animation |
| Carousel arrow | `scrollBy` smooth | `scroll-behavior: smooth`, `auto` under reduced motion |
| Filter sheet (mobile) | Native `<dialog>`; slides up from the bottom, dismisses back down the same path (spatial symmetry) | 320ms, `cubic-bezier(0.32, 0.72, 0, 1)` (critically damped feel, no overshoot); scrim fades 0 to `rgba(14,14,16,.4)` over the same 320ms |
| Sheet dismiss | Tap scrim, close button (`aria-label="Close filters"`), or Escape | Interruptible: reversing mid-transition follows from the current position |
| Sheet drag to dismiss (optional stretch) | Handle drags the sheet 1:1, release velocity decides, rubber-band above the top | Spring damping 1.0, response 0.3s. The planner may defer this; the sheet is complete without it |
| Results updating | Previous results stay, grid drops to 60% opacity | 150ms ease-out; no skeleton flash on a filter change |
| Photo appearing | Opacity 0 to 1 once loaded | 150ms; the box is already reserved so nothing moves |

No bounce on anything that did not start from a flick. No full-viewport or looping animation. Skeletons are static (no shimmer).

Reduced motion (`prefers-reduced-motion: reduce`): sheet becomes a 150ms opacity cross-fade with no transform, press scale is removed, smooth scrolling is off, card hover shadow stays. Reduced transparency (`prefers-reduced-transparency: reduce`): the sticky bar and arrow buttons become solid (`#F5F5F7` and `#FFFFFF`) with no blur. `prefers-contrast: more`: add a 1px `#111114` border to cards, inputs and the sticky bar.

## Accessibility baseline for this phase

Phase 5 owns the full WCAG 2.2 AA pass; this phase must not create debt:

- Every control is a native element (`button`, `a`, `select`, `input`, `dialog`) with a visible label or `aria-label`.
- Contrast: text 4.5:1, large text and control borders 3:1 (values in Color already satisfy this).
- Focus ring is always visible; tab order follows visual order; the sheet traps focus (native `dialog.showModal()`), returns focus to the Filters button on close, and closes on Escape.
- Result count is in an `aria-live="polite"` region so a screen reader hears "24 cars" after a filter change.
- Selected state never relies on colour alone (check icon plus fill).
- Page text zooms to 200% without horizontal scroll at 320px width.
