## Summary

This phase is mostly platform features, not libraries. The stock page is a **dynamic server component** (reading `searchParams` opts it into request-time rendering [CITED: node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/page.md:119]). It parses the URL into a `StockQuery`, asks the single configured `StockProvider` for `{cars, total, page, pageCount, facets}`, and renders. Client components are only the filters, the sheet, a pending-state wrapper, and `PhotoCarousel`. Filters write to the URL with `router.replace` inside `startTransition`, so the server re-renders and the old grid dims to 60% while pending. No new runtime dependency is needed; `sharp` (already a transitive dependency of `next`) is needed as an explicit devDependency for the photo script.

The three non-obvious risks, all verified this session, are: (1) **source photos top out at 938 x 704**, so the UI-SPEC's 1200 x 900 output would be an upscale (use 900 x 675, same 4:3); (2) **`next/image` with the default loader does not work on this Workers setup** (no `IMAGES` binding in `wrangler.jsonc`), so images must be served as static files with `unoptimized`; (3) **cartwright.ie only server-renders 8 of its 57 cars**; the rest load through a nonce-protected internal JSON endpoint that I did not call (an automated permission check blocked it), so how the scraper enumerates all cars is an open decision for the owner.

For the card photo fade and the "failed image" state, client-side `onLoad`/`onError` handlers can fire before React hydrates and be missed, leaving photos invisible. Design the carousel so images are visible by default and JS only adds polish (Pitfall 3).

**Primary recommendation:** Build `src/lib/stock/` as the only data seam (types, `query.ts` URL parse/serialise, `file-provider.ts`, `index.ts` single config point, `contract.test.ts`), generate `demo-cars.json` + `public/stock/**` WebP files (900 x 675, q72, max 6 per car, about 15 MB) with a one-off `scripts/` pipeline, serve images with `images.unoptimized`, and put the browse route in a route group so `loading.tsx` does not swallow the car page's real 404.

### Pattern 2: The `StockProvider` seam (STK-01, STK-03, BRW-01/02/04)
**What:** One interface, one config point, a contract test, and a lint rule that makes "a page imports a concrete provider" a CI failure.

```typescript
// src/lib/stock/types.ts  (proposed shape; names are this research's recommendation, not existing code)
export type Fuel = "petrol" | "diesel" | "hybrid" | "plug-in-hybrid" | "electric" | "other";   // closed set; provider maps its own strings in
export type Gearbox = "manual" | "automatic";
export type SortKey = "newest" | "price-asc" | "price-desc" | "year-desc" | "km-asc";

export interface Car {
  id: string;            // stable source id, e.g. "4508173"
  slug: string;          // "bmw-3-series-2021-4508173"
  make: string; makeSlug: string;
  model: string; modelSlug: string;
  variant?: string;
  year: number; priceEur: number; mileageKm?: number;
  fuel?: Fuel; gearbox?: Gearbox; bodyType?: string; bodySlug?: string;
  photos: { src: string; width: number; height: number }[];
}
export interface StockQuery {
  q?: string; make: string[]; model: string[]; yearFrom?: number; yearTo?: number;
  priceMin?: number; priceMax?: number; body: string[]; fuel: string[]; gearbox?: Gearbox; kmMax?: number;
  sort: SortKey; page: number; pageSize: number;
}
export interface FacetOption { value: string; label: string; count: number }
export interface Facets { make: FacetOption[]; model: FacetOption[]; body: FacetOption[]; fuel: FacetOption[]; gearbox: FacetOption[] }
export interface StockResult { cars: Car[]; total: number; page: number; pageCount: number; facets: Facets }
export interface StockProvider {
  query(q: StockQuery): Promise<StockResult>;
  getBySlug(slug: string): Promise<Car | null>;
  all?(): Promise<Car[]>;   // optional; only for generateStaticParams / sitemap in Phase 2
}
```

**Facet counts must be disjunctive for multi-select groups.** For each group G (make, model, body, fuel, gearbox), count over the cars that pass every filter EXCEPT G's own. Otherwise ticking "Audi" makes every other make show 0 and the buyer cannot add BMW. A selected option always shows its count and stays enabled; zero-count unselected options stay visible and `aria-disabled` (UI-SPEC "Counts" paragraph). Model options come only from selected makes. `q` and all range filters apply to every group.

```typescript
// Source: standard disjunctive faceting; ASSUMED pattern, not from library docs
const passes = (c: Car, f: StockQuery, skip?: "make" | "model" | "body" | "fuel" | "gearbox") => /* each predicate guarded by `skip !== key` */ true;
const countBy = (cars: Car[], f: StockQuery, key: "make" | "body" | "fuel" | "gearbox" | "model") =>
  Object.entries(Object.groupBy(cars.filter((c) => passes(c, f, key)), (c) => valueOf(c, key)))
    .map(([value, list]) => ({ value, label: labelOf(value), count: list!.length }));
```

**Sort:** five keys with a stable tie-break on `id` so pages never reorder between requests. "Newest listed" has no listing date in the scrape (the detail page exposes no date I could find), so the file provider defines it as highest source id first; the id is a CarsIreland-assigned number, assumed to rise over time (A2).

### Pattern 3: URL state and instant filters (BRW-01, BRW-03)
**What:** `query.ts` is the single translation between URL and `StockQuery`, used by the server page (`parseStockQuery(await searchParams)`) and by the client filters (`toSearchParams`). Param names are exactly the UI-SPEC contract [VERIFIED: 01-UI-SPEC.md:172-184, quoting the table verbatim]: `q`, `make`, `model`, `yearFrom`, `yearTo`, `priceMin`, `priceMax`, `body`, `fuel`, `gearbox`, `kmMax`, `sort`, `page`. Sort keys [VERIFIED: 01-UI-SPEC.md:192-198]: `newest` (default), `price-asc`, `price-desc`, `year-desc`, `km-asc`.

Rules to implement and unit-test:
- `searchParams` is `Promise<{ [key: string]: string | string[] | undefined }>` [VERIFIED: page.md:14]. A repeated param arrives as an array: take the first.
- Lists are comma separated, lowercased, de-duplicated, capped (e.g. 20 values); numbers must be finite integers within sane bounds; `sort` must be one of the five keys; `gearbox` one of two; `q` trimmed and sliced to 80 chars. Anything else is ignored, never thrown.
- Defaults are omitted when serialising (`sort=newest`, `page=1`). Any filter change resets `page` to 1 (UI-SPEC does not say this; it is standard and avoids landing past the end).
- A `page` past `pageCount` calls `redirect()` to the last page; with `loading.tsx` present this is a streamed client-side redirect, not an HTTP 307 [CITED: node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/loading.md:105-118]. The e2e asserts the final URL, not the status.
- Round-trip test: `parse(toSearchParams(q)) == q` for generated queries.

**Client wiring (the only subtle React part):**
```tsx
"use client";
// Source: pattern from node_modules/next/dist/docs/01-app/01-getting-started/07-mutating-data.md (useTransition) and use-router.md (router.replace)
const [pending, startTransition] = useTransition();
const navigate = (next: URLSearchParams) =>
  startTransition(() => router.replace(`${pathname}?${next}`, { scroll: false }));
```
`StockShell` is a client component holding `{pending, navigate}` in context and rendering `<div className={pending ? "opacity-60" : ""} style={{transition: "opacity 150ms ease-out"}}>{children}</div>`, where `children` is the server-rendered `StockResults`. The sheet's "Show n cars" button reads `total` from props and sets `aria-busy={pending}`; props update when the new RSC payload lands, so it keeps the last count while pending (UI-SPEC loading row). The search box keeps its own `useState` for the typed value and calls `navigate` 250 ms after the last keystroke; the input is never disabled. `router.replace` input must be a relative URL built from `URLSearchParams` only, never from raw user strings [CITED: use-router.md:54].

Render `StockFilters` twice (sidebar `hidden lg:block`, and inside the dialog). Use `useId()` prefixes for all `id`/`for` pairs so the two copies never share an id.

**What:** `ListingCard` is a server component; `PhotoCarousel` is the one small client component. Structure from UI-SPEC (scroll-snap container, `flex: 0 0 100%` slides, `tabindex="-1" aria-hidden="true"` slide links, dots decorative, arrows only under `@media (hover: hover)`).

### Anti-Patterns to Avoid
- **Filtering in the page or in a client component.** Violates D-05 and breaks STK-03. The page only parses, calls `stock.query`, renders.
- **Naive facet counts (conjunctive).** Makes multi-select unusable (see Pattern 2).
- **`next/image` with the default loader on this Worker** (Pitfall 1).
- **`loading.tsx` at `src/app/used-cars/`.** It wraps `[slug]`, turning a real 404 into a streamed 200 soft-404 and failing D-08's test (Pitfall 2).
- **`error.tsx` for provider failures.** It would replace the whole page including filters; UI-SPEC says filters stay usable. `try/catch` around `stock.query` and render the error state inline.
- **`fs` reads of the data file at runtime.** Workers have no project filesystem; import the JSON statically so it bundles.
- **Sorting or paging by array position without a tie-break.** Results reshuffle between requests.
- **Putting JS-gated opacity on images** (Pitfall 3).

## Common Pitfalls

### Pitfall 1: `next/image` default loader on Workers
**What goes wrong:** `/_next/image?url=…` returns an error in production because OpenNext's optimiser needs a Cloudflare Images binding or a custom loader.
**Why:** OpenNext states "To enable image optimization, you must either define an image binding or use a custom loader" [CITED: opennext.js.org/cloudflare/howtos/image]; `wrangler.jsonc` has no `images` binding [VERIFIED: wrangler.jsonc, keys seen: name, main, compatibility_date, compatibility_flags, assets, services, routes, workers_dev, observability].
**How to avoid:** `images: { unoptimized: true }` in `next.config.ts`; point `src` at `/stock/...webp` static files. The CI `worker` job must also request a page that renders images.
**Warning sign:** works in `next dev` / `next start`, fails only under `wrangler dev`.

### Pitfall 2: `loading.tsx` swallows the 404 status
**What goes wrong:** `notFound()` under a segment with `loading.tsx` returns HTTP 200 with a not-found UI, so the "unknown slug returns 404" test fails.
**Why:** "The response body starts streaming when a Suspense fallback renders (for example, a `loading.tsx`)… Calling `notFound()`… before this point preserves its 404" [CITED: loading.md:118]; the headers are already sent.
**How to avoid:** put `page.tsx` and `loading.tsx` for the list in a route group `used-cars/(browse)/`; `used-cars/[slug]/` is a sibling with no `loading.tsx`. Keep the car page's data fetch synchronous-fast and call `notFound()` first.
**Warning sign:** `curl -I /used-cars/nope` shows 200.

### Pitfall 3: Missed `onLoad` / `onError` before hydration
**What goes wrong:** photos are server-rendered, can finish loading (or fail) before React attaches handlers, so a "fade in on load" state never flips and the photo stays at opacity 0, or a failed image shows the browser broken icon.
**Why:** DOM events that fire before hydration are not replayed to React handlers [ASSUMED, well-known React behaviour].
**How to avoid:** images are visible by default. For the 150 ms fade use a CSS-only entrance on a class set after load with a ref callback that also checks `el.complete`: `ref={(el) => { if (el?.complete) el.dataset.loaded = "1"; }}` plus `onLoad` setting the same attribute; style `img[data-loaded]` only to remove an initial `opacity:0` that applies **only when JS is running** (add the hide class from an effect, not in SSR markup). For failure: `onError` or `el.complete && el.naturalWidth === 0` hides the `<img>` (`visibility:hidden`) so the `#E9E9ED` box shows. Verify with the blocked-image visual test from UI-SPEC.
**Warning sign:** blank cards on a throttled first load that look fine on reload.

### Pitfall 4: Photo upscale and byte budget
**What goes wrong:** following D-03 literally (1200 x 900) upscales photos whose originals are 938 x 704 (bigger files, no extra detail).
**How to avoid:** output 900 x 675 (exact 4:3, a slight downscale). Record this as a deliberate deviation from "1200 x 900" in the plan; the 4:3 ratio, not the pixel size, is what the UI-SPEC relies on. Every `width`/`height` attribute becomes 900/675. At 390 CSS px x DPR 2.6 a phone wants about 1000 px, so 900 is close enough.
**Warning sign:** `sharp` metadata of the sources shows 938 wide.

### Pitfall 5: Binaries are forever in git
**What goes wrong:** re-running the photo script with different settings commits a second 15 MB set.
**How to avoid:** decide format/size/count once on a 3-car trial, measure, then run the full set; commit photos in one commit; content-hashed names mean only changed files change; delete stale files in the script before writing. D-03 flags this as costly.

### Pitfall 6: Lazy-loading expectations in a horizontal scroller
**What goes wrong:** a test asserting "slide 2 is not requested until swiped" flakes: browsers start lazy images within a distance threshold of the viewport, and slide 2 is only one card-width away.
**How to avoid:** assert on the **last** slide (offset about 5 x card width): not requested at page load, requested after scrolling the carousel to the end. Check the `loading="lazy"` attribute on slides 2-6 as the deterministic assertion. Threshold values are browser-specific [ASSUMED].

### Pitfall 7: Facet and filter semantics drift between server and client
**What goes wrong:** the sheet shows a count that disagrees with the grid because the client recomputed something.
**How to avoid:** the client never computes counts; it renders `facets` and `total` from props. The "Show n cars" label uses `total`.

### Pitfall 8: Static page assumptions
**What goes wrong:** the stock page is dynamic (`searchParams`), so it renders in the Worker on every request; the car page can be static. Keep the file provider cheap (60 items, no regex compilation per car) and avoid per-request JSON parsing (a module-level import is parsed once per isolate).
**How to avoid:** precompute lowercased search strings (`searchText`) when building the provider, not per query. Add `generateStaticParams` returning all slugs for `[slug]` so car pages prerender at build [CITED: dynamic-routes.md:199-208 (`generateStaticParams`)]; unknown slugs fall through to `notFound()`. Revisit when a live provider replaces the file.

### Pitfall 9: Duplicate filter DOM
Two copies of `StockFilters` (sidebar and sheet) share names/ids and both receive `change` handlers. Prefix ids with `useId()`; never read form state from the DOM by `name` globally. Both copies read state from the URL, not from local component state, so they cannot disagree.

### Pitfall 10: UI-SPEC pixel values assumed to be inviolable
Header sticky behaviour is under-specified: the spec makes the filter bar sticky "under the header" but never says the header is sticky. Make the header non-sticky and the bar `sticky top-0`, which keeps "only blurred surface" and saves 56 px of viewport on a phone. This is a recommendation within Claude's discretion; flag in the plan.

### Disjunctive facets, one pass per group
```typescript
// Source: standard faceted-search technique; proposed implementation
function facetOptions(cars: Car[], q: StockQuery, group: "make" | "model" | "body" | "fuel" | "gearbox") {
  const pool = cars.filter((c) => matches(c, q, group)); // matches() skips `group`'s own predicate
  const counts = new Map<string, FacetOption>();
  for (const c of pool) { const v = valueOf(c, group); if (v) { const o = counts.get(v) ?? { value: v, label: labelOf(c, group), count: 0 }; o.count++; counts.set(v, o); } }
  // keep currently selected values even at 0 so they can be unticked
  for (const v of q[group === "gearbox" ? "make" : group] ?? []) if (!counts.has(v)) counts.set(v, { value: v, label: v, count: 0 });
  return [...counts.values()].sort((a, b) => b.count - a.count || a.label.localeCompare(b.label));
}
```
(Executor: tidy the gearbox single-value case; the sketch shows intent.) The Model group is empty unless `q.make.length > 0`, and only counts cars whose make is selected.
