## Spacing Scale

Unchanged: 4, 8, 16, 24, 32, 48, 64. Touch targets 44px minimum, primary buttons and inputs 48px, textarea minimum height 112px (multiple of 4).

New uses of the scale:

| Where | Value |
|-------|-------|
| Label to its input | 4px (xs, matches the Phase 1 `SelectField`) |
| Field to field in a form | 16px (md) |
| Group to group in a form (contact block, car block, consent) | 24px (lg) |
| Dialog padding | 16px below 640px, 24px from 640px |
| Dialog footer (submit button) | 12px top, 16px sides, `env(safe-area-inset-bottom)` aware, as the Phase 1 filter sheet footer |
| Car summary row in a dialog | thumbnail 80 by 60, 12px gap to text |
| Heart button on a card | 44px circle, 8px inset from the top and right photo edges |
| Photo tile gap (trade-in) | 8px |
| Form page: top space, heading to intro, intro to form | 48px, 8px, 24px |
| Section gap on the car page (Finance section) | 48px (Phase 2 rule) |

Exceptions:

- Centred dialog (from 640px) is 520px wide. Form pages cap the form column at 640px. Both are multiples of 4.
- Trade-in photo tiles are 4:3 at whatever width three (phone) or four (from 640px) columns give. Remove buttons keep a 44px target even though the tile can be 90px wide.

### Lead dialog (enquiry, test drive, reserve) (D-09, D-10)

A native `<dialog>` opened with `showModal()`, class `sheet` plus a modifier for form dialogs. Reuses the filter sheet and `dialog.sheet` rules in `globals.css`; extend the body scroll-lock rule to cover it.

| Part | Rule |
|------|------|
| Below 640px | Bottom sheet exactly as the Phase 1 filter sheet: docked to the bottom edge, full width, `max-height: 90dvh`, 16px top radius, slides on `transform` in 320ms with `--ease-sheet`, scrim fades with it. Header, body and footer are three rows: header and footer stay put, the body scrolls (`overscroll-behavior: contain`) |
| From 640px | Centred: `margin: auto`, 520px wide, `max-height: min(90dvh, 720px)`, 16px radius on all corners, `shadow-lift`. Opens with opacity 0 to 1 plus `scale(0.97)` to 1 over 200ms `ease-out`; closes the same way back. Reduced motion: opacity only, 150ms |
| Header | Title (Heading) left, close button right (44px, `aria-label="Close"`, `-mr-2` as the filter sheet). The title follows the selected type: `Enquire`, `Book a test drive`, `Request to reserve` |
| Body, top to bottom | 1. Car summary row. 2. Type picker. 3. Type hint (Meta, only for Reserve). 4. Contact fields. 5. Type fields. 6. Message. 7. Consent. 8. Turnstile slot |
| Footer | One full-width 48px accent submit button. Label follows the type: `Send enquiry`, `Request test drive`, `Request to reserve`. While sending it reads `Sending`, is `disabled`, `aria-busy="true"` |
| Close | Close button, Escape, or a tap on the scrim. **Closing never discards typed text**: the fields keep their values in memory for the life of the page and clear only after a successful send. This replaces any "discard changes?" prompt. Nothing personal is written to localStorage or sessionStorage |
| Initial focus | The close button (as the lightbox), never a text field, so the phone keyboard does not cover the sheet on open. Focus returns to the button that opened the dialog on close |
| Keyboard on phones | Fields use `autocomplete` (`name`, `tel`, `email`), `type="tel"` and `type="email"`, `enterKeyHint="next"` (the message uses `enterKeyHint="enter"`). The footer stays visible above the on-screen keyboard (`dvh` sizing); the focused field scrolls into view |

**Car summary row:** 80 by 60 thumbnail (4:3, 12px radius, `#26262B`, first photo, `alt=""`), then to its right the car title (Body strong, clamped to 2 lines) and below it the price (Meta, secondary). Sold cars never reach this dialog. If the dialog is opened without a car (not a case in v1), the row is not rendered.

**Type picker:** the Phase 1 segmented control (`role="radiogroup"`, three equal segments, selected = accent fill, white text and check icon, 44px high, press scale). Segment labels: `Enquire`, `Test drive`, `Reserve`. Legend (visible, Label): `What would you like to do?`. Changing type keeps everything already typed and swaps only the type fields, the title and the submit label; no layout jump above the picker.

**Type fields:**

| Type | Extra fields | Notes |
|------|--------------|-------|
| Enquire | none | Message label `Message (optional)` |
| Test drive | `Preferred day` (native `type="date"`, `min` is tomorrow, optional), `Preferred time` (select: `Any time` default, `Morning`, `Afternoon`; optional) | Meta hint under both: `We will call to confirm a time.` No opening hours are named anywhere in the form (hours are not known until Phase 4) |
| Reserve | none | Message label `Note (optional)`. Hint (Meta, above the contact fields): `This is a request, not a hold. We will call you to confirm. No payment is taken.` (D-11) |

### Form fields, all forms (D-10, D-12)

| Field | Rule |
|-------|------|
| Name | Required. `autocomplete="name"`, max 100 |
| Phone | `type="tel"`, `autocomplete="tel"`, max 30 |
| Email | `type="email"`, `autocomplete="email"`, max 200 |
| Phone or email | Meta line above the two fields: `Add a phone number or an email, so we can reply.` At least one is required (D-12). If both are empty, one error under the email field: `Add a phone number or an email.` and both inputs get the error border |
| Message / Note | Textarea, `maxlength` 1000, minimum height 112px, no resize handle. Optional on car forms. Required on Find a car |
| Consent | See next table |
| Honeypot | A text input in a wrapper that is visually hidden and moved off-screen (not `display: none`), `aria-hidden="true"`, `tabindex="-1"`, `autocomplete="off"`. It has no visible label. A filled honeypot gets the normal success screen, so a bot learns nothing |
| Turnstile slot | Managed widget with appearance `interaction-only` (D-05): invisible for most visitors. The container has zero height and no margin until Cloudflare needs an interactive challenge; then it grows to fit the challenge, directly above the footer button (03-01 spike: 0px when invisible, 71px with a forced challenge). The Turnstile script loads when a form first opens or first receives focus, not on page load (mobile performance) |

**Labels:** every input has a visible `<label>`; placeholders are never labels. Optional fields end with `(optional)` in Meta secondary. Required fields carry no asterisk (most are required or grouped, so the exceptions are marked instead).

**Consent (D-06, D-07):** a 44px-high row, a native checkbox (20px, `accent-accent`, as the Phase 1 filters), label text:
`I agree to Carright using these details to reply to my request. Privacy policy`
where `Privacy policy` is a link to `/privacy` (underlined, text colour, `target="_blank"`, `rel="noopener"`, visually hidden suffix `(opens in a new tab)` so a dialog is never lost). Unticked by default, never pre-ticked. The wording lives in one constant with a version string stored with every lead. There is no marketing checkbox. Error if unticked: `Tick the box to send your request.` The same consent row is used on every form (trade-in, sourcing, finance).

**Validation and errors (LED-01, LED-03):**

- Validated server-side; the client may pre-check but the server message is shown. Native browser validation bubbles are off (`noValidate`); errors are ours.
- On a failed submit, an **error summary** appears at the top of the body: `role="alert"`, Heading text `Check these details`, then a list of links, one per invalid field, each focusing that field. Focus moves to the summary heading, which has `tabindex="-1"`. The summary is replaced, not stacked, on each failed submit.
- Each invalid field: border `#F97066`, message under it (Meta, destructive) linked with `aria-describedby`, `aria-invalid="true"`. The error text always says what to do, never only "invalid".
- Typed values are never cleared by an error (server error, network error, validation error).
- Submitting is blocked while sending (button disabled), so a double tap cannot send twice.

**Success:** the body is replaced by a confirmation, the footer becomes a single secondary `Close` button (on a form page, the confirmation replaces the form card and the button is a link `Back to used cars`). Layout: a 44px circle filled `#F5F5F7` with an ink check icon, Heading text, then Body text (65ch). Focus moves to the heading (`tabindex="-1"`), inside an `aria-live="polite"` container. Copy by type is in the Copywriting Contract. The success state shows only after the lead row is stored; a failed notification email must not turn a stored lead into an error.

**Server and network failure:** a message at the top of the body (`role="alert"`, hairline card, 16px padding, destructive heading text): `We could not send this. Your details are still here. Try again, or call us on {DEALER_PHONE}.` where the number is a `tel:` link. Button re-enabled. Same copy for network failure and for a failed Turnstile check, with the Turnstile variant noted below.

| Field | Rule |
|-------|------|
| Registration | Required. Text, `autocapitalize="characters"`, `spellcheck="false"`, max 12. Placeholder `191-KY-1234`. Saved upper case. Loose validation (letters, digits, hyphens, spaces); no paid reg lookup (D-14) |
| Mileage | Required. `inputmode="numeric"`, suffix `km` inside the field (Meta, secondary). Digits only; commas the buyer types are tolerated and stripped. Range 0 to 999,999 |
| Make, Model | Optional text, max 60 |
| Year | Optional, `inputmode="numeric"`, 4 digits, 1980 to next year |

**Photos (D-13):**

| Part | Rule |
|------|------|
| Legend and helper | Legend `Photos (optional)`. Helper (Meta): `Up to 12 photos. JPEG, PNG or WebP, {PHOTO_MAX_MB} MB each.` The number comes from a constant so the copy and the check cannot drift |
| Picker | Hidden native `<input type="file" multiple accept="image/jpeg,image/png,image/webp">`. The visible control is the **Add photos tile**: 4:3, dashed 1px `#8A8A94` border, 12px radius, `PlusIcon` over the label `Add photos` (Label). It is a real `<label>` for the input, so the keyboard and screen readers get the native control. It is the last tile in the grid and disappears at 12 photos |
| Grid | 3 columns below 640px, 4 from 640px, 8px gap. Each tile: 4:3, 12px radius, `object-fit: cover`, `#26262B` behind the image (preview from the local file, no layout shift) |
| Tile controls | Remove button top right: 44px target, 28px visible scrim-60 circle, close icon, `aria-label="Remove photo {i}"`. No confirmation (re-adding is cheap) |
| Sending | Each photo shows its local preview at once. Photos are sent with the form when the buyer submits (one server action, 03-01 decision), so there is no per-photo state. A photo that cannot be used is refused at pick time with the per-file message |
| Limits | Over the count: the extra files are ignored and a Meta error under the grid says `You can add up to 12 photos.`. Wrong type or too big: `{filename} is not a photo we can use. Use a JPEG, PNG or WebP under {PHOTO_MAX_MB} MB.` The rest of the batch is kept |
| Total size | Before sending, the picker refuses a photo that would take the re-encoded total over `PHOTO_TOTAL_MAX_BYTES` (16 MB), with the per-file message. A request the server refuses for size shows the send-failure copy |
| Announcements | `aria-live="polite"` region: `{n} photos added`, `Photo removed`, `{n} of 12 photos` |
| Resizing | Confirmed: downscale on the device before sending to a 2,000px long edge, JPEG quality 0.82, which strips EXIF and GPS data. `PHOTO_MAX_MB` = 15 applies to the picked original, so a normal phone photo is never refused |

## Accessibility baseline for this phase

Phase 5 owns the full WCAG 2.2 AA pass; this phase must not create debt. The Phase 1 and 2 baselines apply. Additionally:

- Every field has a visible `<label>` linked by `for`/`id`; helper and error text is linked with `aria-describedby`; invalid fields carry `aria-invalid="true"`. Error text states what to do and is never colour alone (text plus border).
- A failed submit moves focus to the error summary heading; each summary link moves focus to its field. A success moves focus to the confirmation heading.
- The dialogs are modal `<dialog>` with `showModal()`: focus trapped, Escape closes, focus returns to the opener, `aria-labelledby` the title. The type picker is a real `radiogroup` of native radios.
- The honeypot is invisible and not focusable (`tabindex="-1"`, `aria-hidden`), so keyboard and screen reader users never meet it.
- The consent link opens a new tab and says so for screen readers. The checkbox is native, 20px control inside a 44px row.
- The heart is a toggle button with a constant label and `aria-pressed`; state is shown by shape (outline or filled) as well as colour. Save and remove are announced in the live region.
- The photo picker is a native file input reached by its label; tile remove buttons are native buttons with `aria-label`s; additions, removals and refused files are announced.
- Calculator results sit in a polite live region; labels, units and the representative-only notice are real text, not images.
- Target size: all controls 44px minimum (the 28px visible remove circle has a 44px hit area), inputs and primary buttons 48px.
- Inputs are 16px so iOS does not zoom; `autocomplete` and `inputmode` values as listed above.
- Text contrast: destructive `#F97066` on `#1A1A1E` is about 6:1 and on `#0E0E10` about 7:1; secondary text `#A1A1AA` as Phase 1.
