# Phase 4: UI Design Contract

> Visual and interaction contract for Reviews and Core Pages (issues #13, #14). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
> This file extends `01-UI-SPEC.md`, `02-UI-SPEC.md` and `03-UI-SPEC.md`. It does not restate them. Every token, type size, weight, colour, radius, motion rule, reduced-motion rule, icon rule, button rule and copy rule in those files applies unchanged. **No new colour, type size, weight, radius or spacing value is added.**

Sources: `04-CONTEXT.md` (D-01 to D-09), the three earlier UI-SPECs, REQUIREMENTS.md (REV-01..03, PGS-01..04), `.claude/CLAUDE.md`, and the code in `src/app/page.tsx`, `src/app/layout.tsx`, `src/app/privacy/page.tsx`, `src/components/SiteHeader.tsx`, `SiteFooter.tsx`, `landing/LandingPage.tsx`, `stock/ListingCard.tsx`, `leads/LeadPage.tsx`, `JsonLd.tsx`, `src/lib/site.ts` and `globals.css`. Nothing else sits in the hero (no second button, no banner).
2. **Featured stock.** `h2` `Latest arrivals`. The six newest in-stock cars from `stock.query` (newest sort, sold cars excluded), shared `ListingCard`, grid 1 / 2 / 3 columns (sm / lg) with 24px gaps. No new client component: the card already carries what it needs (Phase 3 adds the heart to the card itself).

4. **How we can help.** `h2` `How we can help`, one Body line `A local dealer in Tralee, Co. Each card is one `<a>` (so one tab stop): `#1A1A1E`, hairline border, 16px radius, 16px padding, title Body strong, description Meta secondary, `ChevronRightIcon` right, 44px minimum height, press scale 0.97, hover shadow only on `(hover: hover)`. This section merges "why buy from us" and the CTAs (D-04): selling-point claims (warranty, history checks, years trading) are the dealer's to supply and are not invented here.

### Reviews strip and card (REV-01, REV-02, D-01 to D-03)

**Data shape the UI consumes** (the provider contract; fixtures and Places both produce it): `{ source: "demo" | "google", rating?: number, count?: number, placeUri: string, reviews: { id, author, authorUri?, photoUri?, rating: 1 to 5, text, relativeTime, languageCode? }[] }`. Pages never branch on `source` except for the `Demo reviews` pill and JSON-LD.

**Section:** `h2` `What customers say`. Under it, the aggregate row (only when `rating` and `count` exist): the number (Display, tabular) beside a row of five 20px stars, then Meta `Based on {count} Google reviews` and an underlined 44px link `See all on Google` to `placeUri` (`target="_blank"`, `rel="noopener noreferrer"`, visually hidden suffix `(opens in a new tab)`). The stars show the exact average by a clipped overlay: a filled row whose width is `rating / 5` inside an outline row, pure CSS, no half-star icons. A visually hidden sentence carries the meaning: `Rated {rating} out of 5 from {count} Google reviews`; the star graphics and the visible number are `aria-hidden`. If only reviews exist (no aggregate), the row is skipped and the cards show alone.

**Strip:** `<ul>` inside a `role="region"` container with `aria-label="Google reviews"` and `tabindex="0"` (keyboard users can scroll it; focus ring visible).

| Width | Layout |
|-------|--------|
| Below 1024px | Horizontal scroll strip, no JavaScript: `overflow-x: auto`, `scroll-snap-type: x mandatory`, cards `snap-start`, `overscroll-behavior-x: contain`, the strip bleeds to the screen edge (`-mx-4 px-4`, `scroll-padding-inline: 16px`). All reviews returned (Places returns at most 5). Cards 256px wide below 640px, 320px from 640px |
| From 1024px | A 3 column grid, 16px gaps, the first three reviews; the rest carry `lg:hidden` |

Smooth scrolling is off under reduced motion; the browser default scrollbar is kept (no custom scroll chrome).

**Review card:** `<article>`, `#1A1A1E`, hairline border, 16px radius, 16px padding, 12px between blocks, equal height in the grid (`flex flex-col`, footer pinned to the bottom).

1. Star row: five 16px stars, `aria-hidden`, with a visually hidden `Rated {rating} out of 5`.
2. Text: Body, `lang` set from `languageCode` when present, **never altered**. Visually clamped to 8 lines with `line-clamp-8` (the DOM keeps the full text, so screen readers and copy get all of it). No expand control; the footer link reaches the full review on Google.
3. Footer row: optional 40px circle profile photo (`#26262B` behind it, `alt=""`, fixed `width`/`height`, `loading="lazy"`, `referrerPolicy="no-referrer"`; a plain `<img>`, not `next/image`, because the host is Google's; add the one-line lint disable with the reason). **Only rendered when `photoUri` is supplied; no initials or stock avatar otherwise.** Next to it: author (Body strong; a link to `authorUri` when supplied, `target="_blank"`, `rel="noopener noreferrer"`, hidden suffix `(opens in a new tab)`), and below it Meta secondary `{relativeTime}`.
4. Attribution: Meta secondary `Google` after the relative time, separated by a middle dot and 8px (`{relativeTime} · Google`). Wording lives in one `GoogleAttribution` component so the official logo asset can replace the word in one place if Google's current display policy requires the logo (Open items).

**Demo state (Deviation from D-01):** while `source === "demo"` the section shows a `Demo reviews` pill at the top of the section (same shape as `Placeholder figures`) **in every environment**, not only non-production. Reason: the pitch site is live on a public demo domain and a fictional review shown as real is the worst failure this phase can have. Removing it is the provider swap. Fixtures are clearly fictional: five entries, first name and an initial (`Sample customer A.`), ratings 5, 5, 5, 4, 5, one or two plain sentences, no named cars or staff, no claims beyond buying a car. `relativeTime` strings are fixed (`a month ago`).

**Failure behaviour (D-03):** the Places provider has a 3 second timeout and returns `null` on any error, bad status, empty list or malformed body; the page renders without the section. No error text, no retry button, no placeholder box. The result is cached for a day (`fetch` revalidate); the page awaits it (no `Suspense`, which would shift the layout when the section pops in or is dropped).

### /contact (PGS-02, D-05)

`h1` `Contact`, intro `Call us or come and see us.` Phones: one column. From 1024px: two columns (`1fr 1fr`, 32px gap): details left, map right. Order of blocks:

1. Accent button `Call {DEALER_PHONE}` (`tel:`, phone icon, full width below 640px, auto from 640px with 240px minimum).
2. `Address` (`h2`), then `<address>` in Body: `{street}`, `{town}`, `{county}`, `{eircode}` one per line, from `site.ts`. Placeholders render as bracketed text, for example `[Street address]`.
3. `Opening hours` (`h2`), then a `<dl>`, one row per day (Monday to Sunday): day left, hours right (`9am to 6pm`, or `Closed`), 1px hairline under every row, 12px row padding, as the Specifications list. Times are stored as 24 hour `HH:MM` strings and formatted in one function; no "open now" status (needs the client clock, and the page is cached).
4. Text links, underlined, 44px: `Ask us to find a car` to `/find-a-car`, `Sell your car` to `/sell-your-car`.
5. **Map** (below the details on phones, right column from 1024px): a `#1A1A1E` box, hairline border, 16px radius, `aspect-ratio: 4 / 3` reserved from first paint (no layout shift). Default state, no third party loaded: the address in Body, a secondary button `Show map` (48px) and an underlined link `Get directions` to `https://www.google.com/maps/search/?api=1&query={encoded address}` (add `&query_place_id={GOOGLE_PLACE_ID}` when known). `Show map` is the only client code: it swaps the box content for a `<iframe src="https://maps.google.com/maps?q={encoded address}&output=embed" title="Map of {SITE_NAME}, {town}" loading="lazy" referrerpolicy="no-referrer-when-downgrade">` filling the same box. Nothing from Google loads until the tap, so there is no cookie or consent issue and no cost to Lighthouse. Without JavaScript `Get directions` still works. If the iframe cannot load, the visitor still has the link; no error text is added.

## JSON-LD (PGS-03, D-07)

One `dealerJsonLd()` function in `src/lib/` builds the object, rendered through the existing `JsonLd` component (it already escapes `<`) on `/` and `/contact` only, not on every page.

| Property | Rule |
|----------|------|
| `@context`, `@type`, `@id` | `https://schema.org`, `AutoDealer`, `{SITE_URL}/#dealer` |
| `name`, `url`, `logo`, `image` | `SITE_NAME`, `SITE_URL`, `{SITE_URL}/brand/logo.png` for both |
| `telephone` | `DEALER_TEL` (E.164) |
| `address` | `PostalAddress`: `addressLocality` Tralee, `addressRegion` Co. Kerry, `addressCountry` IE. `streetAddress` and `postalCode` are included **only when `DEALER_FACTS_CONFIRMED` is true** |
| `openingHoursSpecification` | From the hours data (`dayOfWeek`, `opens`, `closes` as `HH:MM`; closed days left out). Included **only when `DEALER_FACTS_CONFIRMED` is true** |
| `aggregateRating` | `AggregateRating` with `ratingValue` and `reviewCount`, **only when `source === "google"`** and both exist. Never from fixtures. Valid markup, but Google does not show review stars for a business's own reviews, so none is expected; it is kept for completeness (D-07) |
| Omitted | `geo`, `priceRange`, `sameAs`, `review`, `areaServed` (no confirmed facts; empty or invented values fail review) |

Unit test on shape: required keys present, no `undefined` or placeholder strings (`[`) in output, `aggregateRating` absent for demo, address and hours absent while unconfirmed. The Phase 2 car and `ItemList` JSON-LD are unchanged. Validate once with Google's Rich Results Test and Schema.org validator against the deployed demo; record the result in the PR.

## Accessibility and performance constraints

Phase 5 owns the full WCAG 2.2 AA pass; this phase must not create debt. Phase 1 to 3 baselines apply. Additionally:

- One `h1` per page, `h2` per section, no skipped levels. Landmarks: `header`, `main`, `footer`, `nav` labelled `Main` and `Footer`. `<address>` for the address, `<dl>` for hours, `<ul>` for lists.
- Stars and the rating graphic are `aria-hidden`; the rating is a sentence in text. Rating is never colour alone.
- The review strip is a focusable named region so keyboard users can scroll it; each card is static content, so no extra tab stops except the author link.
- Every external link (`authorUri`, `placeUri`, directions) opens in a new tab with `rel="noopener noreferrer"` and a visually hidden `(opens in a new tab)`. `tel:` links are real anchors.
- All targets 44px, search input and primary buttons 48px, inputs 16px text (no iOS zoom). Text contrast as Phase 1 to 3: `#A1A1AA` on `#1A1A1E` and on `#0E0E10`, white-on-`#D0111A` buttons all pass AA.
- Home is a server component with no new client JavaScript. The only new client code in the phase is `Show map`. No web font, no hero image, no third-party script at load. The profile photos are lazy and have explicit dimensions; the reviews fetch has a timeout and a day of caching so it never blocks the response; every box that fills late (map, photos) is reserved first.
- Lighthouse budget for the home page (Phase 5 gate): mobile 95 or more. Nothing in this contract may cost it: no auto-playing media, no layout shift, LCP is text.
