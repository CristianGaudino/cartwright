<objective>
Issue #13 (REV-01, REV-02, REV-03): a `ReviewsProvider` with demo fixtures and a swappable Places API (New) provider, and a reviews section that carries the attribution Google requires, shown on the home page.

Purpose: the home page (#14, plan 04-04) needs reviews; the client's Google place ID and key do not exist yet, so fixtures stand in and the Places provider goes live by setting two env vars, with no page change (D-01, D-02, D-03).
Output: `src/lib/reviews/*`, `ReviewsStrip`, `PlaceholderPill`, `StarIcon`, the section on `/`, unit and E2E tests.

Branch `feat/reviews-core-pages` (stacked on `feat/finance`, PRs #48 to #51 unmerged, D-08). No PR in this plan: the single PR for #13 and #14 opens at the end of 04-04.

Policy note (REV-02, refines D-02 and the UI-SPEC open item on Google's display policy): Google's Places policy (developers.google.com/maps/documentation/places/web-service/policies, read 2026-11-07) requires the text `Google Maps` (not `Google`) when no Google map is shown, in white, black or #5E5E5E, Roboto first, 12 to 16px; a notice saying how reviews are ordered; a link to Google's review policy (https://support.google.com/contributionpolicy/answer/7422880); a link from every review to that review on Google Maps; author name, link and avatar when available; and a notice when a review is translated. This plan follows the policy where the UI-SPEC copy says `Google`; each change is listed for the owner in the 04-04 PR.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker -> Google Places API | The API key leaves the Worker in a request header |
| Places response -> page | Third-party review text, names and URLs are rendered to visitors |
| page -> Google image host | Visitors' browsers fetch profile photos from Google |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information disclosure | GOOGLE_PLACES_API_KEY | high | mitigate | Read only in `src/lib/reviews/index.ts` (imports `server-only`), sent only as the `X-Goog-Api-Key` header, never in a URL, prop, thrown message or log; not `NEXT_PUBLIC_` and not in `next.config.ts` env; the provider has no console calls (unit test) |
| T-04-02 | Tampering | Places response rendered on `/` | medium | mitigate | Every field checked by type; only https URLs become `href` or `src`; text is rendered as React text, never raw HTML |
| T-04-03 | Denial of service | Places latency and per-call cost | medium | mitigate | `AbortSignal.timeout(3000)`; any failure returns null and hides the section; a success is reused for 24 hours per isolate plus `next.revalidate` 86400 |
